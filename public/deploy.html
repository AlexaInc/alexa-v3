Full Deployment Guide

A complete, no-assumptions walkthrough — for someone who has never deployed this bot before and doesn't know what an environment variable is. Every single setting the bot reads is explained here: what it does, whether you actually need it, exactly where to get the value, and what to type.

0

What you'll end up with

By the end of this guide you will have: a WhatsApp number that runs the Alexa bot 24/7, a MySQL database storing group settings and bot data, and this web Control Panel at /dashboard. You sign in there with the bot-issued WhatsApp LID and password from .profile; configured owners are recognised automatically, with no separate owner login. The owner dashboard shows live CPU/RAM/network data and logs. No coding required — just copying values into one file called .env.

1

Get a server to run it on

You need something that stays powered on to run Node.js continuously. Pick one:

  • Easiest — a free PaaS. No server management at all. Click one of these and follow their on-screen setup (you'll still need Steps 3 below to fill in variables in their dashboard instead of a file): Koyeb · Replit · Railway.
  • Full control — a VPS. Rent a cheap Linux server (e.g. from any VPS provider), SSH into it, and follow every step on this page exactly as written.
  • Using Docker? This repo ships a Dockerfile — build it with docker build . -t alexa-v3 and run with docker run -p 8000:8000 --env-file .env alexa-v3 once you've prepared your .env file in Step 3.
2

Get the code & install dependencies

On your VPS terminal (skip this exact form if you clicked a PaaS deploy button above — it clones the repo for you automatically):

apt update && apt install -y speedtest-cli ffmpeg
git clone https://github.com/AlexaInc/alexa-v3.git
cd alexa-v3
npm install

This downloads the bot's code and every library it depends on. It does not start the bot yet — you must configure it first (Step 3), otherwise it will crash or run with broken features because it doesn't know your database, your WhatsApp number, or its owner identities.

3

Understand the .env file

🔑 This is the single most important step. Read it fully before moving on.

An environment variable is just a named setting the bot reads when it starts — things like "what's my database password" or "who is allowed to log into the admin panel". Instead of writing these directly into the code, they live in one plain-text file called .env, in the format NAME=value, one per line.

This repo ships a template called env_dummy with every variable already listed (with placeholder/example values). Your first move is to copy it and rename it: 

cp env_dummy .env

Now open .env in any text editor (nano .env on a VPS) and replace every placeholder with your real value, using the reference below. If you're deploying on a PaaS instead of a VPS (Koyeb/Railway/Replit/Hugging Face Spaces), you won't have a .env file at all — instead, open your service's dashboard, find "Environment Variables" or "Secrets", and add each NAME / value pair there one by one, using the exact same names shown below.

⚠️ Never commit a filled-in .env file to GitHub or share it publicly — it contains passwords and secret tokens.

🔴 Required variables — the bot will not work correctly without these

Panel security & owner identity
Owner_nb / Owner_id Required

These are the bot owner identities. The panel has no separate owner username or password.

How it works: first use the normal bot-issued WhatsApp LID and password to sign in. If that authenticated account matches Owner_nb or Owner_id, it is automatically given the owner dashboard. 
Owner_nb=94766045156,94723966801
Owner_id=78151912841263,209032400879844
SESSION_SECRET Required

A private key the server uses to cryptographically sign your login session cookie, so nobody can forge a fake "logged in" cookie.

How to set it: generate a long random string — you never need to remember it, it's just used internally. Run this on any machine with Node.js installed and paste the output: 
node -e "console.log(require('crypto').randomBytes(32).toString('hex'))"
MySQL Database — stores group settings, conversation history, tasks
DB_HOST Required

The network address of your MySQL server.

How to get it:
  1. Create a free MySQL database — aiven.io has a genuinely free tier that works well for this bot. (Any other MySQL host — PlanetScale, Railway MySQL, a self-hosted server — works the same way.)
  2. After creating the service, its dashboard shows connection details: Host, Port, User, Password, Database name.
  3. Copy the Host value here — it looks like mysql-xxxxx-yourproject.aivencloud.com.
DB_HOST=mysql-abc123-myproject.aivencloud.com
DB_PORT Required

The port your MySQL server listens on.

How to get it: same dashboard as DB_HOST above — it's shown right next to it. Standard MySQL port is 3306, but managed providers like Aiven often use a custom port (e.g. 14322) — always use the exact number your provider shows you, not the default. 
DB_PORT=14322
DB_NAME Required

The name of the specific database (schema) the bot should use inside your MySQL server.

How to get it: same dashboard. Most providers create a default database for you already (often called defaultdb) — you can use that, or create a new one named e.g. alexa_bot. You do not need to manually create any tables — the bot creates them itself the first time it connects. 
DB_NAME=defaultdb
DB_UNAME Required

The username the bot logs into MySQL with.

How to get it: same dashboard — usually shown as "User". Aiven's default is often avnadmin. 
DB_UNAME=avnadmin
DB_PASS Required

The password for the MySQL user above.

How to get it: shown once when you create the database, and always retrievable from the same dashboard afterwards. Copy it exactly — MySQL passwords are case-sensitive and often contain symbols, which is fine.
Bot & Owner Identity — who owns the bot, which number it runs on
bot_nb Required

The WhatsApp phone number the bot itself will run on (the number you'll scan a QR code with, or link as a device).

How to set it: type the number in full international format, digits only, no +, no spaces, no leading zero. Example: a Sri Lankan number 077 123 4567 becomes 94771234567. 
bot_nb=94771234567
Owner_nb Required

Your own WhatsApp number — the person who controls the bot and receives owner-only messages (like the restart notification). Can be different from bot_nb.

How to set it: same international digits-only format as above. You can list more than one owner separated by commas. 
Owner_nb=94766045156,94723966801

🟢 Optional variables — leave blank to skip that feature, nothing breaks

Extra bot identifiers
Owner_id Optional

Your WhatsApp platform ID (LID), used in newer WhatsApp accounts alongside phone numbers for owner checks.

Use the numeric LID(s), with no @lid suffix. More than one value is supported: separate each LID with a comma. Most setups work with just Owner_nb, but setting both formats gives the most reliable owner detection.
Owner_id=78151912841263,209032400879844
spc_nb Optional

"Special"/sudo numbers that get elevated permissions without being a full owner.

Comma-separated numbers, same digits-only format. Leave blank if you don't need a separate moderator tier.
spc_nb=94771442053,94703812053
ocid Optional

The ID of an official WhatsApp group where the bot is an admin, used for broadcast features.

Format is a group JID like 1234567890@g.us. Get this by adding the bot to a group and checking the logs, or using the .gp / group-info command once the bot is running. Leave blank if unused.
Web panel extras
WEBHOOK_SECRET Optional

Secret used to verify GitHub webhook requests (if you wire up auto-deploy-on-push via the /github-webhook route).

Only needed if you use the GitHub webhook integration. Generate the same way as SESSION_SECRET above. If left blank, the webhook endpoint still works but without signature verification (anyone could call it) — a warning is printed to the logs reminding you.
AI Chatbot (optional — bot works fine without any AI configured)
CHAT_MODEL Optional

Which AI model powers the .chatbot on / AI web search features.

Example values: gpt-4o, gemini-1.5-pro, claude-3-5-sonnet. Get an API key from whichever provider you choose and set the matching key below. Leave the whole AI section blank to simply not offer AI chat features.
GOOGLE_API_KEY  +  GOOGLESEARCH_ENGINE_ID Optional

Powers Google-backed web search commands (.web, .aiweb).

  1. Go to Google Programmable Search Engine and create a search engine → copy its Search engine ID into GOOGLESEARCH_ENGINE_ID.
  2. Go to Google Cloud Console → Credentials, create an API key, enable the "Custom Search API" for it, and paste the key into GOOGLE_API_KEY.
HF_TOKEN Optional

Hugging Face access token, used for certain AI model inference calls.

Get one free at huggingface.co/settings/tokens → "New token" → Read access is enough.
DEEPAI_API_KEY Optional

Used by the image-related AI module for extra generation/analysis features.

Sign up at deepai.org to get a free key. Leave blank to skip DeepAI-specific features only.
NIGHTAPI_AUTH Optional

Token for the NightAPI service, used by a subset of content commands.

Only needed if you specifically use NightAPI-backed commands — otherwise leave blank.
TENOR_API_KEY Optional

Powers GIF-search related features via Tenor.

Get a free key at tenor.com/developer.
Custom Quiz Packs (MongoDB — separate from the main MySQL database)
QUIZ_MONGO_URI Optional

Connection string for a MongoDB database that stores custom quiz packs used by .setquiz and .quiz <id>.

Get a free MongoDB cluster at MongoDB Atlas → "Connect" → "Drivers" → copy the connection string and replace <password> with your database user's password. Without this set, the quiz feature is simply disabled (a warning is logged, nothing crashes).
QUIZ_MONGO_URI=mongodb+srv://user:pass@cluster0.xxxx.mongodb.net/alexa
YouTube Downloads (optional fine-tuning — sensible defaults already work)
YTDL_AUDIO_FORMAT Optional

Preferred output format when the bot downloads a song for .song/.play.

Accepted values: native, mp3, opus. Leave blank to use the default.
YTDL_RELAYS Optional

Comma-separated list of relay-server URLs to route around YouTube's bot detection, if downloads start failing.

Only relevant if you self-host a relay (an advanced/rare setup) — safe to leave blank for a normal deployment.
Networking / Proxy (advanced — only needed behind a restrictive network)
PROXY_URL Optional

Routes all outbound bot traffic through an HTTP/HTTPS/SOCKS proxy.

Only needed if your hosting provider blocks direct outbound connections (some restricted regions/networks). Format: http://user:pass@proxyhost:port. Leave blank for a normal setup.
4

Start the bot & scan the QR code

Once every required variable above is filled in and saved in .env (or your PaaS dashboard):

npm start

This runs app.js, the process supervisor — it starts both the WhatsApp connection (src/index.js) and this web panel (src/server.js), and automatically restarts either one if it crashes, recording exactly why/when in data/restarts.json (shown to you as the owner on WhatsApp the next time it restarts).

Watch the terminal — a QR code will print directly in the console. On your phone: open WhatsApp → Settings → Linked Devices → Link a Device → scan it. Once linked, the bot is online and will respond to commands like .menu in any chat.

5

Log in to the Control Panel

Open this website's Alexa panel and sign in with the bot-issued WhatsApp LID and password. When that account matches Owner_nb or Owner_id, the owner diagnostics dashboard opens automatically.

6

Final checklist

  • .env created from env_dummy (or PaaS environment variables set) — every 🔴 Required variable above is filled in
  • MySQL database created and reachable — DB_HOST/DB_PORT/DB_NAME/DB_UNAME/DB_PASS all correct
  • npm install completed with no errors
  • npm start shows a QR code and no "missing environment variables" warning in the console
  • WhatsApp linked successfully — .menu replies in a test chat
  • Signed into the Alexa panel with a bot-issued WhatsApp LID/password; configured owners receive owner access automatically
